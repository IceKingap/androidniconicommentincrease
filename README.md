# コメント増量 — Android向けニコニコ動画クライアント

動画を再生しながら、大量のコメントを動画時刻に同期して表示するAndroidプロジェクトです。日本語・ダークテーマ・Android 10（API 29）以降に対応します。動画取得、動画再生、コメント描画を分離し、独自の中継サーバーは使いません。

0.6.0では、設定・動画一覧・コメントのタブへ移っても同じ再生WebViewを維持し、アプリ内のタブ移動で音声が途切れない構成にしました。動画中央に再生・一時停止と±10秒の操作を置き、画質・音質・再生速度・音量は「再生設定」にまとめています。端末のホームへ移るなど、アプリが背面へ回ると一時停止します。

動画詳細に投稿日時、再生数、コメント数、いいね数、タグ、投稿者を表示します。タグからタグ検索へ、投稿者から動画・ショート・シリーズの一覧へ進めます。キーワード検索とタグ完全一致検索を切り替え、検索履歴は端末に最新30件まで保存し、個別削除・全削除できます。初回の並びは再生数順で、変更後は前回の並び順を使います。

描画の優先設定は「コメント量優先」が既定です。この設定のALLは表示件数を自動で減らしません。「FPS優先」は描画負荷に応じて表示件数の上限を調整し、ALLでも一部を省略します。取得済みコメントはどちらでも保持し、表示量の調整で削除しません。

過去コメントは投稿日時をさかのぼって段階的に取得します。初回分はすぐ表示し、既定で初回込み10ページ／スレッドまで自動追加します。途中停止・手動追加・取得予算の変更に対応します。同じ応答を複製して件数を増やす処理ではありません。動画ID/URL入力はヘッダーの「ID / URL」、縦画面の同期コメント一覧は「コメ欄」から開きます。

0.3.0のhls.jsによるMSE動画再生と、0.4.0の同一WebView内での動画・コメント合成について、POCO F7 Ultra / Android 16での成功がユーザーから報告されています。4種類の人工HLS動画では、デスクトップブラウザの最終合成画像に動画・コメント両方の画素があることも確認しました。動画情報HTTP406の公式視聴ページJSONへの1回限定フォールバック、おすすめ・検索・フォロー新着は継続します。認証・会員・地域などの制限がある場合は停止して理由を表示します。

動画再生とコメント描画には更新済みのAndroid System WebViewが必要です。Android 10初期搭載版のままのWebViewは対象外です。コメントのWebGL2が使えない場合はCanvas 2Dへ切り替えます。今回のWebView版は動画とコメントを同じページで重ね、動画の実時計をコメントへ渡します。Media3/platform版は別のコメントWebViewを使用します。

**0.6.0の実機動作と、実APIでの再生・コメント追加取得・タグ検索・投稿者一覧は未検証です。** 過去版のユーザー報告を0.6.0の動作確認結果として扱いません。この開発環境ではニコニコへの外向き通信とAndroid実機の接続ができていません。API実装は調査した現行OSSに基づきます。ビルドとローカル描画の確認範囲は [TEST_RESULTS.md](TEST_RESULTS.md) に記録します。

## 起動と使い方

1. APKをAndroid端末にインストールします。
2. 「動画一覧」のおすすめ・検索・フォロー新着から動画を選ぶか、ヘッダーの「ID / URL」ボタンで入力欄を開き、`sm9` などのIDや公式URLを入力して「開く」を押します。共有メニューからテキストURLを渡すこともできます。
3. 動画のコントロールはタップで開閉します。中央に再生・一時停止と±10秒、下にシーク、右上に「再生設定」「コメ欄」「全画面」を表示します。動画のバッファ待ちや一時停止中はコメント時計も停止します。
4. 描画倍率を選びます。基本の上限は**1倍=同時描画100件、2倍=200件、…100倍=10,000件。コメント量優先のALLは同時描画上限なし**です。FPS優先では倍率の上限に加え、描画負荷に応じた上限も適用します。これは本アプリ内の上限の定義で、公式プレイヤーとの同数保証ではありません。倍率変更ではコメントを再取得しません。
5. 初回は全対象スレッドを取得してすぐ表示し、既定で初回込み10ページ／スレッドまで過去ログを自動追加します。「コメント」タブで自動取得ON/OFFと5・10・20・50・100ページの予算を選べます。再生画面の「追加取得を停止」で途中停止、「コメントを追加取得」で現在位置から最大5ページずつ追加・一時エラー後の再開ができます。取得済みデータとスレッド別カーソルを保持するため、同じページを最初から取り直しません。APIが返す取得可能範囲と、サービスに保存された全履歴は異なります。
6. 「コメント」タブで文字サイズ、透明度、流れる速さ、重なり、CA優先、30/60 FPS、表示範囲、描画品質、キャッシュ、デバッグと優先設定を変更できます。「コメント量優先」が既定です。「FPS優先」は目標FPSを継続して下回ると表示件数を減らし、余裕が戻ると増やします。調整は表示だけに適用し、取得データは削除しません。設定は端末に保存し、タブ移動中も再生音声は継続します。
7. 「再生設定」で画質・音質・0.5〜2倍速・音量を変更できます。「最高画質」「最高音質（画質上限内）」が既定で、自動ABRを意味しません。画質・音質の変更時は視聴権限を再取得し、再生位置・停止状態・取得済みコメントを維持します。画質・音質の選択を端末に保存し、次の動画でも対応候補があれば適用します。
8. 縦画面の「コメ欄」を押すと、動画の下に再生時間順のコメントを表示します。動画時刻に追従し、指でスクロールすると追従停止、「再生位置へ」の下向きボタンか開き直しで再開します。行を押すとその時刻へシークします。画面付近の行だけを遅延描画し、表示済み行の独自画像キャッシュを蓄積しません。逆方向シークとコメント描画のため、取得済みコメント本文は保持します。
9. 動画詳細のタグを押すとそのタグで検索し、投稿者名・アイコンを押すと投稿者の動画・ショート・シリーズへ進めます。投稿日時・各件数と折り畳める説明も表示します。取得できない値を推測して埋めません。

通信なしで確認するには「設定」→「オフライン描画テスト（12,000件）」を選びます。オリジナルの30秒H.264動画と12,000件の人工コメントを同梱しています。これはAPI動作の証明にはなりません。

## 動画一覧

| タブ | 内容 |
| --- | --- |
| おすすめ | 公式の総合24時間ランキングによる人気動画。公式ホームの個人向け推薦とは異なります |
| 検索 | 公式スナップショットのキーワード／タグ完全一致検索。再生数順・コメント新着順・投稿が新しい順、追加読み込みと検索履歴 |
| フォロー新着 | 公式のフォロー動画feed。アプリ内の公式ログインで認証後に取得し、追加読み込みに対応 |

動画はサムネイル・タイトル等を平坦な一覧に表示し、選ぶと独自のコメント増量プレイヤーで開きます。公式ページで一覧を見る場合も、そこで選んだ動画を独自プレイヤーへ渡せます。「公式視聴」の再生フォールバックは公式プレイヤーを使います。フォロー新着のログイン前には認証を案内し、ログアウト・認証変更時は以前の一覧と進行中の取得結果を破棄します。

検索は「キーワード」と「タグ」を切り替えられます。初回は「再生数順」で、選択した並び順と検索モードを保存します。次の検索・タブ往復・追加読み込み・アプリ再起動でも同じ順を使います。検索履歴は語とモードの組で重複をまとめ、最新30件を端末に保存します。「検索履歴」から再検索・個別削除・全削除でき、履歴を使う際の並び順は現在の選択を引き継ぎます。検索結果は公式サイトの通常検索と反映時刻・件数が異なる場合があります。Snapshotに投稿者名がない場合はIDを表示し、取得できない再生・コメント件数は作らず非表示にします。詳細は [動画一覧API調査](docs/catalog-api.md)。

投稿者画面には動画・ショート・シリーズの3タブがあり、シリーズを選ぶと収録動画へ進めます。ショートの `ss...` は対応する公式ショートURLで視聴し、通常動画の直接再生へ渡しません。チャンネルの一覧は公式ページを使い、動画タブは公式チャンネルの動画一覧、ショート・シリーズは公式チャンネルトップへ案内します。取得失敗と公開項目がない状態を区別し、追加ページの失敗では取得済みの一覧を保持します。詳細は [投稿者画面](docs/creator-screen.md)。

テスト動画は音声なしの640×360 / 30FPSです。再生成する場合だけ、開発用にPyAV・OpenCV・NumPyを用意して `python tools/generate-demo.py` を実行します。アプリの利用・ビルドにPythonは不要です。

## ビルド

Android Studioでこのフォルダーを開いてください。JDK 17、Android SDK Platform 35、Build Tools 34.0.0、Gradle 8.9を使います。`local.properties` に自分のSDKパスを設定します。依存バージョンはこの環境の既存キャッシュと互換性を持たせています。

| Flavor | 再生エンジン | ビルド |
| --- | --- | --- |
| `webview` | hls.js 1.7.3 / WebView MSE、今回のAPK | `./gradlew :app:assembleWebviewDebug` |
| `media3` | AndroidX Media3 ExoPlayer 1.5.1 / HLS | `./gradlew :app:assembleMedia3Debug` |
| `platform` | Android標準 MediaPlayer / HLS、従来版 | `./gradlew :app:assemblePlatformDebug` |

Windowsは `gradlew.bat` を使います。各Flavorの画面・API・コメント描画は共通です。この環境での更新用ビルド対象は `webviewDebug` です。Media3版のライブラリはこの開発環境に存在せず、外部からの依存取得も拒否されました。取得確認・再開方法は [Media3ビルド調査](docs/media3-build.md)。Android標準MediaPlayerのHLSはMPEG-2 TSが保証範囲で、今回疑われる分割MP4との互換性問題に対応するためWebView MSEを選びました。実際のエラー原因を配信形式に確定したわけではありません。

APKの標準出力先:

- `app/build/outputs/apk/webview/debug/app-webview-debug.apk`
- `dist/comment-increase-0.6.0-debug.apk`（今回の更新用APK）
- `app/build/outputs/apk/platform/debug/app-platform-debug.apk`（従来エンジンをビルドした場合）
- `app/build/outputs/apk/media3/debug/app-media3-debug.apk`（Media3版をビルドした場合）

本環境専用のキャッシュ参照設定は `tools/environment-build.ps1` にあります。通常環境では不要です。このスクリプトはユーザー既存キャッシュを読み取り専用で参照し、作業用Gradle homeをプロジェクト内に作ります。

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\environment-build.ps1
```

## 構成

- `app/src/main/java/jp/commentflow/data/` — 動画ID解析、watch情報、HLS access-rights、コメント取得、ページング、Cookie、キャッシュ。
- `app/src/webview/` / `app/src/media3/` / `app/src/platform/` — 同じインターフェースの動画再生エンジン。
- `app/src/main/java/jp/commentflow/player/HlsAssetSource.kt` — 取得済み視聴権限のあるCDNだけへ通信するHLSデータソース。URI書換・AES鍵・Range・429待機・セッション破棄に対応。
- `app/src/main/assets/` — hls.js、niconicommentsとコメント描画・同期時計。実行中の外部JavaScriptダウンロードはありません。
- `CommentSurface.kt` / `CommentOverlay.kt` — コメントモジュールの共通インターフェース。WebView版は動画と同じページ、他Flavorは透明WebViewを使います。公式ページ用WebViewとは別で、公式ページにはJavaScript bridgeを公開しません。
- `CommentTimelinePanel.kt` — 縦画面での同期コメ欄。二分探索による時刻追従と遅延行表示。
- `BrowseController.kt` / `BrowseSearchPreferences.kt` — キーワード・タグ検索、並び順と端末内履歴の保持。
- `CreatorController.kt` / `CreatorScreen.kt` / `VideoDetails.kt` — 投稿者・シリーズの一覧と、動画詳細のタグ・投稿者への導線。
- [API調査](docs/api-research.md)、[動画一覧API調査](docs/catalog-api.md)、[投稿者画面](docs/creator-screen.md)、[HLSエラー調査](docs/hls-playback.md)、[WebView動画再生](docs/webview-player.md)、[コメント合成調査](docs/comment-compositing.md)、[描画設計・比較](docs/renderer.md)、[環境調査](docs/environment.md)。

## 認証・失敗時の動作

ゲスト視聴を先に試します。「設定」からニコニコ公式サイトでログインできます。パスワードを独自収集せず、WebViewとネイティブAPIはAndroid CookieManagerを共有します。Chromeとの自動共有は前提にしません。Cookieはアプリ専用領域でOS保護され、ログや独自の平文ファイルに出力しません。Androidのバックアップを無効にしています。

取得された視聴権限で利用できるストリームだけを選びます。URL、権限キー、threadKeyは動画ごとに取得し、期限が返れば再取得に使います。通信失敗時の自動再試行は最大3回、コメント呼び出しは最低1秒間隔、429はRetry-Afterに従います。権限作成POSTは無断再送しません。利用不可・認証切れ・仕様変更は理由を表示し、「公式視聴」で公式プレイヤーを開けます。公式プレイヤー内では独自コメント描画を重ねません。

コメントキャッシュはアプリ専用領域に15分・約40MBを目安に保存し、認証状態ごとに分離します。ディスクキャッシュを無効にしても、現在の取得済みデータはメモリに保持して追加取得を継続します。「コメントキャッシュを削除」で消去できます。

過去ログは同じ視聴権限のまま取得を試み、ログイン要求・権限拒否・末尾・取得位置が進まない応答では停止して理由を表示します。ゲストキーは過去ログに使えないとする参考実装の実測があり、追加取得にログインが必要な場合は「ログインして追加取得」を表示します。ログイン状態が変わると旧取得を止めて新認証で取得し直します。取得中は件数だけを随時更新し、重い全コメント描画の更新は約5秒間隔・完了・停止時にまとめます。実サービスでの増加件数は未確認で、ページ数倍の件数は保証しません。

## 検証と制限

```text
./gradlew :app:testWebviewDebugUnitTest :app:lintWebviewDebug
node tools/renderer-tests.mjs
node tools/renderer-browser-test.mjs
python tools/generate-player-fixtures.py
node tools/player-browser-test.mjs
node tools/player-comment-browser-test.mjs
```

ブラウザ検証スクリプトの実行環境は [描画設計](docs/renderer.md) を参照してください。デスクトップブラウザとAndroid WebViewでは性能・フォント・GPU動作が異なります。コメント量優先のALLは上限による省略を行いません。FPS優先ではALLでも表示件数の上限を自動調整します。投稿者の非表示コマンド、不正データ、描画失敗は別途診断し、目標FPSや全CA再現を保証しません。

0.6.0の実機・実API確認は未実施です。確認すべき内容は、公開動画のゲスト再生、コメント同期、過去ログ権限、ログイン保持・失効、長時間のHLSセッション更新、設定タブ往復時の音声継続、検索と履歴、投稿者・シリーズ一覧、公式ショート視聴、画面回転、端末ごとの大量描画とFPS優先の調整です。DRMや会員制限を回避しません。
